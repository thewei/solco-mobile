- `failure-grace.ts` — freeze-then-repair for network changes: `blocksScreen` lets a connectivity failure replace a screen only when it has no data, the failure is not about the way in (401/pin), or `useFailureGrace` (30 s) elapsed; otherwise Home keeps its list, the status line says `Reconnecting…` and the refetch fills in. Chat stream keeps its frame/live phase across a client swap (only another pane resets it); detail screens (quota, file, diff) keep stale data over a failed refresh; the Terminal's reconnect timer opens with the latest client.
- `background-bridge.tsx` — the app-wide owner of what must outlive backgrounding on Android: the single `useTreeEvents` socket (shared through `useLiveTreeEvents`, so Home and the bridge never open two), the keep-alive foreground service (paired → held in the foreground and background alike; its notification is the live status line `Needs you: N · Working: N · Idle: N` from `keep-alive-status.ts`, pushed with `update`; keyed on "has a client", not on the client identity, so a relay/P2P/direct route switch never bounces it), and the desktop-rule attention notifications (heads-up channel `attention-3`; posted under the stable identity; foreground and background take the same path — only the pane on screen is skipped; stale ones withdraw; the runtime POST_NOTIFICATIONS permission is asked at startup and a `setNotificationHandler` lets the OS show them while the app is open) with tap-through to the pane. Mounted once in the root layout. Registers the `agent-reply` notification category (Reply text action, `opensAppToForeground:false`) and sends a typed reply through `client.sendChat` (the Chat composer's own Herdr-gated path); a refusal is told in a second notification. For a `needs-attention` event it posts the plain notification at once, then reads the pane's Chat card up to 3 times (1 s apart) and upgrades the same notification in place with Approve/Deny; a tap answers through `answerChat` for that card id (a moved-on card is refused → an `Answer not delivered` notification), never opening the app.

- `queries-v3.ts` — SC-06 Chat reconnect safety: useChatStream socket generation fences prevent old WS close/frame/async GET probe from mutating a new connection; retries coalesce into one timer, no-conversation/pane-gone immediately clears the old transcript; recoverable network reconnect keeps existing visible frame. Go Host v3 queries: bootstrap + instance pick (connectivity failures are reported by `use-connection-health`, not retried here), tree (events-hinted refetch with a 20 s fallback), per-pane peek, the events socket with capped backoff, and `useChatStream` (whole-state frames; 4404 ends the follow, 4409 / 409 no_conversation shows the empty state yet re-checks every 3 s because a just-launched agent has no session file for a few seconds; a socket refused before any frame asks `GET chat` why (409 no_conversation / 404 gone) because a WebSocket client cannot read the upgrade status; other closes reconnect with the same backoff); `useGitStatus` / `useGitDiff` (staleTime 0, no retry); `useGitWrite` (one stage/unstage/commit/sync mutation at a time per Workspace; a success sets the status query from the answer, a refusal re-reads it); `useHostQuota` (the Mac's quota page read through the Host's own TTL cache — opening the view reads once, pull-to-refresh forces past the reuse window, never polled); `useRemoteDesktopInfo` (the Mac's Remote Desktop readiness, never polled, refetched when the screen is shown); `useHostProbes` (does each paired Mac answer — the active one reads the shared bootstrap, others are probed on demand); a successful bootstrap stamps the Mac's last-connected time and phone network once per recovery and hands its `net.addresses` to the provider's `noteNet` (the Mac's own serving address joins the card); a 401 forgets that Mac. The events socket also carries the Host's 5 s `hb` frame: once the first `hb` arrived, 13 s of silence counts as a dead path and signals a failure to the ConnectionManager (an older Host without `hb` is never watched).

Rule: this layer owns server state and transport orchestration only; screens never call fetch/WebSocket and no state is persisted as a second Host truth.
