Members:
- `host-connection-v3.ts` — the shape of one v3 connection (host, port, pinned fingerprint, device token, optional registered relay endpoint) and the legacy single-connection parser used for the one-time migration; `relayBaseUrl` = `<r>/c/<secret>`.
- `host-book.ts` — (also `fallbackAddresses`/`adoptAddress`: when the current address does not answer, an earlier one that does becomes the Mac's address; `mergeAdvertised`: the Mac's own bootstrap `net` addresses join the card's history — current > advertised (true now, `lastUsedAt` 0) > answered (true in the past) at the 5-address cap, so a changed LAN/Tailscale address is never starved out) the phone's list of paired Macs in SecureStore: one record per certificate fingerprint (pairing the same Mac over a new address merges into one card and keeps the old address, max 8 Macs × 5 addresses), pure ops (pair/activate/touchConnected/remove/sort), `hostRoute` (LAN/Tailscale/USB from the address alone) and `recordRoute` (relay while `lastRoute` says so). A pairing link's relay endpoint (`relay`) is kept with the card but is an endpoint, never an address — it never enters `addresses[]`; a relay connect stamps `lastRoute: 'relay'`, cleared once a direct address answers. Removing the active Mac leaves nothing active; nothing switches silently. Tested.
- `tailcat-transport.ts` — the Mac's built-in tunnel as a `PinnedTransport` over the `solco-tailcat-transport` native module (one client per Mac fingerprint, node key in SecureStore; `resetTailcatClients()` rebuilds every client with the same key after a network change or a failed probe, requests wait for it). The tunnel address is a bearer capability: never logged. Pairing through it (`pairWithHost` direct 3 s → tunnel) starts the card on `tailcat`; a Mac paired before the tunnel is enrolled once reached (`enrollTunnel`, `setTailcat`, 10-minute guard).
- `phone-network.ts` — the phone's network kind (Wi-Fi/cellular/other/unknown) via expo-network, stored on a Mac's card at connect; no SSID, IP or location is read.
- `byte-chunks.ts` — `concatBytes`: coalesce frame chunks so a renderer encodes base64 once per bridge call (`ghostty-terminal`).
- `page-keys.ts` (+ test) — `PAGE_UP`/`PAGE_DOWN` (`ESC[5~`/`ESC[6~`: Herdr `send_keys` has no named PageUp/PageDown, so they travel as literal input) and `pagesFromDrag` (drag distance → whole pages, never counted twice) for the terminal page's PgUp/PgDn keys and page-scroll rail.
- `pane-grid.ts` (+ test) — `adoptPaneGrid`: the Host's `pane` message (the Mac pane's cell size; Herdr's observer is only a top-left window onto it, no reflow/cursor follow) → on Android pin the terminal view's grid to it and restart the stream there; iOS/web keep fitting their own view.
- `use-phone-network.ts` — `usePhoneNetwork()`: the phone's network kind for error pages.
- `connection-manager.ts` — the one connection policy: a pure state machine (injected clock/probes/route applier) fed by signals (network change, failure, alive, foreground/background). It races the candidate routes (`raceRoutes`: a quick direct answer ends the race at once, relay is the fallback), scores by RTT (`chooseRoute`: direct wins unless the best fallback is clearly faster; between the relay and the Mac's tunnel the faster answer serves — no fixed rank), gives the relay probe the desktop-matched 8 s cap, retries on a 1/2/4/8/10 s ladder (30 s after 8 failures), re-checks a better route on a 15/30/60/120 s ladder while on relay/tailcat, folds bursts (300 ms network debounce, 1.5 s gap) and stays quiet in the background. When a race leaves the route unchanged it calls `refresh()` for every reason (not only a network change): the provider then leaves any P2P link and rebuilds the client, because a silent events socket on a half-open P2P channel is exactly what a `failure` signal is. Tested with fake timers.
- `route-optimizer.ts` — the leftovers the manager does not own: P2P retry ladder (`nextP2PDelayMs`), `p2pAfterTrouble` (a P2P link that dies within 5 min doubles the wait before the next attempt on the same ladder; one that held wipes the record), `describeRouteChange` (the toast wording), `withTimeout`, the 5 s probe/notice constants. Tested.
- `p2p-codec.ts` / `p2p-tunnel.ts` / `p2p-session.ts` — WebRTC P2P to the Mac, pure + injected peers (vitest with a fake peer): `p2p-codec` utf8/base64 and the 1-byte-header fragmenter/reassembler (16 KiB), `p2p-tunnel` the relay-role frame client over a channel (request/openSocket/fail), `p2p-session` `openP2PRoute(signalling, createPeer)` (ICE → offer → answer → channel open, 12 s budget; `OpenP2PRoute.onClose` fires only for non-quiet closes). `ice-gather.ts` decides when the non-trickle offer is worth sending (gathering complete, or 1.5 s after the first reflexive candidate, ceiling 6 s — a dead STUN/TURN server no longer holds every attempt for the whole timeout; vitest with fake timers). `p2p-native.ts` is the only file importing react-native-webrtc (Hermes has no `Promise.withResolvers` — use `new Promise`) (`p2p-native.web.ts` returns null: no P2P on Web). The provider's `connectP2P` overlays a live channel on a relay-routed Mac (client = `createHostClientV3(transport, connection, p2pRoute)`), drops it when the Mac leaves the relay, holds a Mac that answers 404 for 10 min, and keeps a fresh link only if `bootstrap` over it is no slower than over the relay (best of 3 vs 2, `p2pBeatsRelay`, 30 ms slack; a loser is closed and not retried for 2 min — a TURN-relayed path often takes the same detour as the relay); `use-connection-health` starts the first attempt the moment the route is the relay (no wait) and retries on a 15 s → 5 min ladder.
- `rd-native.ts` — with `p2p-native.ts` the only react-native-webrtc importer: `getRdPeerFactory()` (one RTCPeerConnection per Remote Desktop session — a receive-only video transceiver preferring H.264, an ordered `control` channel, an unordered `pointer` channel with maxRetransmits 0, a complete non-trickle offer via `ice-gather`, 6 s of grace for a transient `disconnected`) and `RdVideo` (RTCView, `objectFit: contain`); `rd-native.web.ts` is the inert Web twin.
- `use-after-transition.ts` — `useAfterTransition()`: false until the native-stack push animation ends (`transitionEnd`, 450 ms fallback); the Chat WebView and the Sessions list mount after the slide, behind a skeleton.
- `use-now.ts` — a ticking `now` so relative times age on screen.
- `use-debounced.ts` — `useDebounced(value, delay = SEARCH_DELAY_MS)`: the value once typing has paused; the one 300 ms delay every search that asks the Mac waits (Sessions, Files).
- `host-client-v3.ts` — SC-06 OMP WS: all Chat full frames are sequence-anchored (legacy seq optional), `chat_delta` applies only to exact prior seq/pane via `features/chat-web/host-delta.ts`; on malformed/missing suffix requests exactly one `{t:snapshot}` per gap and waits for full recovery; socket reconnect starts with a clean baseline. Still only caller of `/api/v3`.
- `host-client-v3.ts` — the only caller of `/api/v3`, on two routes: route=lan over the pinned transport, route=relay (`connection.relay`) over the JS layer's own fetch/WebSocket to the registered relay (Bearer header; WS token in the query, no subprotocol): pairWithHost, bootstrap/tree/peek, events, terminal and chat sockets, `launch` (POST /launch, 160 s timeout; refusals as `HostV3Error{code}`), `chatCatalog`, `uploadAttachment` (POST ./chat/attachments, base64 JSON, 120 s), `chatSubagent` (GET ./chat/subagents/{id}, the drawer), `gitStatus`/`gitDiff` (read-only), `gitStage`/`gitUnstage`/`gitCommit`/`gitSync` (POST ./git/*, manage scope, long timeout, each answers the fresh status; needs `capabilities.gitWrite`; refusals as `HostV3Error{code}`, see `GIT_WRITE_REFUSALS`), `sessions` (GET /sessions?q=, read-only catalog metadata + running link), `quota` (GET /quota, read-only; 30 s timeout so a forced refresh can wait out the Host's slowest provider), `chat`/`sendChat`/`stopChat`/`answerChat` (close 4404 = gone, 4409 = no conversation; Host refusals surface as `HostV3Error{code}`); one `HostV3Error` family (unauthorized/pin/http/protocol/transport); a 502–504 without the Host's own error body (alma-relay answers `502 {"error":"<text>"}` when no Mac is behind the code) carries `code: 'relay_offline'`, and `routeAnswered` is the one rule for "this probe reached the Host" (a 401 did; a pin mismatch or an offline relay did not). `continueSession(instance, sessionId)` (POST /sessions/{id}/continue, long launch timeout, needs `capabilities.sessionContinue`). `transcribe({dataBase64, mime})` (POST /voice/transcribe, long timeout, needs `capabilities.voice`).
- `host-client-v3.ts`（Vault）— `vault()` / `vaultItems()` / `vaultAnswer(id, allow)` / `vaultReveal(ref)`: the phone's four calls to the Mac's Vault seam (`/vault…`, capability `vault`); a reveal is `no-store`, never retried, and its value is returned to the caller only — no cache, no log.
- `host-v3-provider.tsx` — lifecycle owner of the paired Hosts (load the book once — every action awaits it —, pair, switchTo, remove, probe any Mac, markConnected, noteNet, 401 drop of that Mac); `connection`/`client` stay stable while the active Mac's transport fields do; a direct pair refuses without a native pinned transport, a relay pair (registered by the QR's r/rt) needs none; recovery races the current/earlier addresses with the relay endpoint and records the winner (relay win = the route, never an address). Route changes go through `applyDecision` (the only writer of routes into the book), `signal()` feeds the ConnectionManager, and an `epoch` rebuilds the client so open sockets reconnect. `noteNet` merges every bootstrap answer's `net.addresses` into the active card (cert-pinned channel, so it can ride the relay) and restarts the ladders when something is new — a fresh address is probed within seconds while on the relay; the route probes (`probeDirect`/`probeRelay`) merge too. `leaveP2PAfterTrouble` is the one way a P2P link is dropped by trouble (refresh or its own close): it records the early death (`p2pDeaths`) and sets the per-Mac `p2pHold`; route probes count a 401 as an answer (`answered`) and leave the revoked phone to the queries' forget-on-401.
- `pairing-v3.ts` — strict parser for the Go Host's `solco://pair?h&p&fp&c&n[&r&rt]` link (fingerprint-pinned, hand-rolled query parser for Hermes, optional relay endpoint — half-specified relay refuses) plus the pair request URL/body. `pairTargetParams` is the one builder of the /pair route params (scan.tsx uses it so the relay `r`/`rt` is never dropped between scan and pair — a bug that left cards direct-only).
- `terminal-keys.ts` — pure core of the terminal's single key row: `KEY_ROW`, `keyInput` (named keys vs xterm Home/End/PgUp/PgDn literals, sticky Ctrl/Alt), `composeTyped` (typed letter + armed modifier → chord; IME phrases never compose), `isRepeatKey`. `terminal-prefs.ts` + `terminal-prefs-storage(.web).ts` — the remembered pinch font size (6–24 dp; unreadable input = default). Round 2: `FN_ROW`/`F_KEY` (F1–F12 as named keys), `ignoresMods`.
