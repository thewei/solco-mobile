Members:
- `_layout.tsx` — root composition: global providers (HostV3Provider), the BackgroundBridge (the one events socket, the Android background keep-alive service and attention notifications), pairing gate to /connect, and the Web-only centered phone shell. The v2 events bridge, connection driver and banner are no longer mounted.
- `+html.tsx` — Web static-export HTML template and PWA metadata; the only place allowed to render `<html>`.
- `(home)/_layout.tsx` — the Home drawer navigator (expo-router's own `Drawer`, push-style, edge-swipe) holding the bottom tabs; `(home)` and `(tabs)` are route groups so Home stays `/`.
- `(home)/(tabs)/_layout.tsx` — the bottom tab bar (designs/mobile-projection nav A): Agents · Changes · Files · Sessions · Quota via expo-router `Tabs`; a tab whose capability (`git`/`files`/`sessions`/`quota`) the Host does not advertise is hidden (`href: null`); the Agents tab badges how many agents need you. Pushed screens (Chat, Terminal, Compose…) cover the bar.
- `(home)/(tabs)/changes.tsx` / `files.tsx` — the project-scoped tabs: `ProjectHeader` (≡ + project chip, client-local choice in `state/project-store`, `features/host/use-project`) over the shared `ChangesView` / `FilesView`; deeper Files levels and previews push `files/[workspaceId]` and `files/view`.
- `(home)/(tabs)/index.tsx` — Home (the Agents tab) (option C of designs/mobile-shell): ≡ opens the sessions drawer, ⚙ opens Connection (a Monitor button beside it opens Remote Desktop when the Host offers it), and the title carries a small line under it (`connectionLine`: route · `Reconnecting…` · `Mac offline` · `Needs re-pairing` · `Can’t reach`); body = Needs you / Working panes with a peek line, or a quiet greeting. An agent row opens its Chat (when `capabilities.chat`), other rows their terminal. Client-local; never moves Mac focus. When bootstrap advertises `launch`, the new-session `LaunchComposer` sits at the bottom.
- `automations/` — the Automations screens (entered from Home's bolt button when `capabilities.automations`, or by tapping an automation notification): `index.tsx` the list, `[name].tsx` the detail, `edit.tsx` New / Edit, `ask.tsx` Let an Agent Draft. Detail, edit and ask need `capabilities.automationsManage`; against an older Host `index` stays the read-only list. `index.tsx` — the list: one card per automation — state dot, name, `Draft/Paused · schedule · agent · Headless`, the newest run in words, `Next in …` — failed and drafts first, a scheduler-not-running line, pull to refresh; refetches when an `automation` events frame arrives. With management: New, Let an Agent Draft, Mark all seen and Start Scheduler buttons, and a card opens its detail. `[name].tsx` — state and schedule, Approve (a draft) / Run Now / Pause · Resume / Edit / Delete (an `Alert` confirm), the plugin's facts, rationale and prompt, and the newest runs (status · trigger · when · duration, no error text) with an Open button when the run's pane is still in the phone's tree; opening it marks the newest unread run seen. `edit.tsx` — name (new only), schedule presets or the five cron fields, repository (typed or a folder the Mac knows), agent (the Mac's own list under the plugin's ids), model, run-as, starts-in, overlap, limits, rationale and prompt; a new automation is always a draft, approved on its detail. `ask.tsx` — `LaunchComposer` prefilled with the desktop's draft brief (`draftPrompt`) so a real Agent on the Mac drafts it (`--draft`, approved later by the person). The Mac's plugin owns everything and every refusal sentence (`features/host/automations-model.ts`).
- `assistants/` — the Assistants screens (Home's bot button when `capabilities.personalAgent`): `index.tsx` the list (counters in words, New Assistant, Needs You), `[id].tsx` one Assistant's page (Needs you / Watching / Tasks / Done / Remembers; Watch a PR draft, pause/resume, rename; a run opens its Chat/Terminal only when its own Herdr session + pane id are in the phone's tree), `approvals.tsx` the cross-Assistant inbox, `style/[id].tsx` Work style (capability `personalAgentPersona`: revision-fenced instructions with history/restore, Agent/Model/Effort profile + the Agents really running, per-server MCP grants with a Check that reports configured/allowed/bound/connected apart). Second client of the desktop `/assistants` page: the Go core on the Mac is the authority, every write is one exact route with requestId + expectedRevision (+ actionHash for approvals), a refusal re-reads the Mac's truth; `memory/[id].tsx` Memory (capability `personalAgentMemory`: add / edit / approve / forget with revision fences, an item's versions, the core's duplicate / stale / conflict notes) and `behavior/[id].tsx` Behavior (capability `personalAgentProactivity`: level, quiet hours, reminder spacing, daily budget); goal completion and tasks creation stay on the Mac.
  - 2026-11-04 (Assistants 3.1 U1): `index.tsx` is the Chats list (Assistant = round-initial avatar row, Group = stacked avatars) with one `+` sheet (New Assistant / New Group only with `capabilities.personalAgentGroups`); `[id].tsx` opens the Coordinator's shared Chat straight away once it is live (`?manage=1` keeps the admin page; the chat ⋯ menu carries "Assistant" when opened from a contact); `group/[id].tsx` is the real group chat (Go-authoritative feed polled every 2 s: authors, exact @ + picker, Reply quote, delivery marks, core receipts, live task cards, starting/blocked Agent status line with Open Terminal — the phone can never speak for an Assistant); `new-group.tsx` picks 2–4 active Assistants.
- `desktop.tsx` — the Remote Desktop device list (entered from Home's Monitor button when `capabilities.remoteDesktop`): every paired Mac from the host book with its online/offline state (probes re-checked every 10 s), route and address; an online one is switched to and opens `/desktop-session`, an offline or unpaired one explains itself (Check again / Pair again), Edit renames (a phone-only nickname) or forgets a Mac, + pairs another; online Macs first, the most recently opened leading each group. No second registry — `useHostV3` stays the book.
- `desktop-session.tsx` — Remote Desktop session of the chosen Mac: the lobby (the Mac's readiness from `GET /remote-desktop`, Control | View only, quality tier, Connect → "waiting for approval on your Mac") that becomes the full-bleed `RemoteLive` session once the Mac approves; a refusal or an ended session returns to the lobby with the sentence. One session at a time; leaving the screen ends it; a link that drops mid-session reconnects by itself ("Reconnecting…" view, Cancel).
- `connect.tsx` — the Mac list (cards: status, address, route, last connected; switch / reconnect / forget) plus pair another by QR or pasted `solco://pair` link; the only config surface.
- `scan.tsx` — QR scanner (expo-camera, QR only): validates the link with `parsePairUrl` and hands it to `/pair` exactly once; nothing scanned is stored or logged.
- `pair.tsx` — `solco://pair` deep-link route: one pinned pairing attempt per code (single-use; a new link arriving while the failure page is up pairs again without restarting the app).
- `chat/[paneId].tsx` — v3 Chat (P2/P3): the desktop's own Chat page (`generated/chat-page.ts`, built from solco/frontend) in `ChatPageView`; this screen wires the Host chat stream and Send/Stop/Answer operations into a `features/chat-web` controller. It also owns the pending launch hand-off: a `pending-<requestId>` pane id (from Home's light composer or compose's send) carries folder + kind + prompt; the screen runs the POST /launch itself while the prompt stands in as the transcript's first row over a working shimmer, adopts the real pane when it answers, and on a failure keeps the row with the sentence above the composer (sending again relaunches). The body zooms in from the opened-from card (`ZoomIn` + `lib/zoom-origin`); the page cross-fades out of the spinner cover (`onReady`). The identity bar is a plain view at the top of the screen body (`headerShown: false` — the native header's custom subviews attach unreliably at mount on Android, and the custom-header container thrashes here): a two-line title (agent name over provider · Workspace · age), status slot, and one ⋯ menu (Changes when the Workspace is known, Terminal when the pane has one, Close = leave this screen). Host refusals reach the page as sentences. Attachments need `capabilities.attachments`.
- `files/[workspaceId].tsx` / `files/view.tsx` — read-only Files (needs `capabilities.files`): one folder level (folders first, size on files; links shown, not followed) and a file preview (text/Markdown as numbered monospace rows, an image, a sentence for binary/too-large/cut files). "Attach to chat" (paperclip, needs Chat) picks an agent and opens its Chat with `@path ` as the draft — the user reviews and sends. Reached from the Files tab and from Chat's ⋯ menu.
- `changes/[workspaceId].tsx` — (pushed; the Changes tab shows the same `ChangesView`) read-only Git status of a Workspace (branch + ahead/behind, Staged / Changes / Untracked groups); a row opens `changes/diff.tsx`, the single-file unified diff (add/delete colours, horizontal scroll, binary/too-large notices). Reached from Chat's ⋯ menu and Terminal's `ChangesButton`; shown only when bootstrap advertises `git`.
- `terminal/[terminalId].tsx` — v3 terminal: the phone's own observe grid in xterm, direct typing, whole-line input and a key row; reconnects, ends on close 4404.
- `(home)/(tabs)/quota.tsx` — the Quota tab, the Mac's agent-quota page (needs `capabilities.quota`): `ProjectHeader` (fixed title) over a summary row (tightest limit, next reset, sources live) and one card per readable provider — level-toned bars (≥80 warn / ≥95 bad, the desktop's thresholds), used/left, reset countdown, pace warning, notes — and one honest line per source that is off or unreadable on the Mac. Pull to refresh forces past the Host's reuse window. Purely read-only; what is read is decided entirely by the Mac's own switches and consents.
- `compose.tsx` — the advanced new-session composer (entered from Home's card with its draft): the shared Chat page (`features/chat-web` controller, unchanged page) as an empty draft conversation with the full composer — `/` `$` catalog, `@` files and attachments come from the Host's pane-less `/launch/catalog|files|attachments` by folder + agent kind; folder/agent chips. The first agent send replaces this screen with the pending Chat screen (`pending-<requestId>`: folder + kind + text; the launch runs there while the prompt already stands in as its first row); a terminal send still runs the `client.launch` round-trip and replaces the screen with the pane's terminal. "Open Terminal" on the empty page opens a plain shell in the folder. The body zooms in from Home's composer card.
- `(home)/(tabs)/sessions.tsx` — the Sessions tab, the Mac's session history (needs `capabilities.sessions`): a search box (300 ms debounce, searched on the Mac) over a RUNNING NOW group — sessions an Agent runs right now, status pill (Running / Needs you / Ready / Open), tap opens that pane's Chat — and the HISTORY / MATCHES rows below, which are information only (no transcript or Continue on the phone yet). The running link is the desktop's own exact-identity match, so the badge and the desktop pill never disagree. Non-running rows carry a Continue pill when the Host advertises `capabilities.sessionContinue`: one Mac-side transaction at a time, the tap is the confirmation, and the answer opens that pane's Chat (`launchRoute`); refusals show as one line under the search box (`continueFailureMessage`).
  - Sessions Trash（`capabilities.sessionTrash`，2026-11-02）：非运行行的行尾 ⋯ 或长按 → 动作菜单（Move to Trash 即确认，或 Select several 进入多选，底栏一次移入 N 条，逐条调用 Host、拒绝的单独说明）；提示条带 Undo（放回本次移入的全部）；搜索框旁的 Trash 切换列出已移入条目并 Put back；永久删除不在手机提供（只在桌面）
- `share.tsx` — "Share to Solco" destination picker (Android text/links via `features/share`): the shared text, the Mac's agents (Needs you / Working / Idle; a tap replaces this page with that agent's Chat, the text as its draft — the user reviews and sends) and a `LaunchComposer` prefilled with it (`initialPrompt`, `replace`); nothing is sent automatically.


Rule: screens compose providers and consume Host queries/state hooks; transport, WS, and machine scheduling never live here.
