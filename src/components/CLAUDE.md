# components/
> L2 | Parent: ../CLAUDE.md

Members:
- `icon.tsx` — the only way a screen draws an icon: `Icon` (lucide glyph at 1.5 px round-capped lines, absolute stroke, size/tone steps from `theme/tokens` `icons`) and `IconTile` (the glyph on a rounded tinted tile). No screen passes its own size, color string or strokeWidth.
- `header-menu.tsx` — `HeaderMenu`, the ⋯ bar button and its anchored dropdown card (plain RN Modal over a dimmed backdrop, OptionSheet's pattern): secondary top-bar actions as `{ label, icon, tone?, separated?, onPress }` rows.
- `remote-desktop/` — Remote Desktop's screens: `remote-surface.tsx` (the Mac's picture on a surface laid out once at the frame's pixel size, zoom/pan as a UI-thread transform of it plus a decay fling — never a per-frame relayout, which reallocates the Android surface buffer and lags — over a transparent touch layer, where a tap on the black bars toggles the menus instead of clicking, feeding `GestureEngine`, plus the trackpad cursor), `remote-live.tsx` (the session screen: auto-hiding top row — End, link line, landscape — and bottom dock — Windows = Mission Control, Desktop = Show Desktop, Type, Keys, More —, a floating touch/trackpad button, key panel and compose bar docked above the soft keyboard via `KeyboardDock`, options sheet for pointer mode / Show Mac pointer (`cursor.set`) / quality / display / landscape / stats / clipboard, notices, keep-awake), `remote-controls.tsx` (the sheet's shared rows: `Group`, `ToggleRow` on the platform Switch, `SegmentedRow`, `ChoiceRow`, `ActionRow`), `remote-keyboard.tsx` (`KeyPanel` and `ComposeBar`: Unicode/IME/dictation as `text.insert`, ⏎ and ⌫ as keys; long-pressing a shortcut pins it to the quick-key row above the dock). `remote-live.tsx` also carries the pinned quick-key row and the clipboard "Sync automatically" switch. Privacy/lock (2026-11-03): the live menu's "Mac screen" group toggles the Mac's blackout (`privacy.set`), and `session.state.locked` raises a lock banner (menus come up) with an Unlock button when `canUnlock` (`unlock.request`; the password lives on the Mac only). Update 2026-11-03: `virtual-keyboard.tsx` is the full on-screen Mac keyboard, kept short (2026-11-03 round 2: 28/34 px caps, 3 px gaps, four-row swipeable pages — main letters/numbers/esc ⇥ ⇧ ⏎ ⌫ , . /, symbols & F1–F12 & navigation, shortcuts — over ONE fixed bottom row ⌃⌥⌘ space ←↓↑→ plus the page key that names the next page, no page dots; ⌃⌥⌘⇧ latch once/locked and combine, keys fire on release so a page swipe never types, hold = repeat, long-press a shortcut pins it) replacing the old key strip; `drag-button.tsx` is the draggable Touch/Trackpad button (snaps to the nearest side edge, place saved in prefs); while a keyboard panel is open the picture shrinks into the free area; a lost link keeps the session screen up with the frozen picture dimmed and a "Reconnecting to your Mac…" pill (from attempt 2 a line names why the last try failed).
- `goal-progress.tsx` — U3's read-only Assistants surface: `GoalPlanBlock` (plan under a Goal card: criteria, milestones with the core's derived state, next action) and `FactsStrip` (the latest ledger lines, labelled "Solco record" — the system's sentences, never the Assistant speaking); both hide when the Host (`personalAgentPlans`) or the Goal has no plan; `RoutinesList` (U4, `personalAgentRoutines`) lists the Assistant's scheduled work read-only — a draft waits for the approval card in Needs you, an enabled one shows next/last run.
- `tap.tsx` — `Tap`, the one press feel (Tamagui `quick` transition: scale 0.97 + a fade); replaces TouchableOpacity everywhere.
- `pill-button.tsx` — `PillButton` (primary / soft / danger, optional glyph, compact/fill): the app's one rounded call to action.
- `text-field.tsx` — `Field`, the one filled text input of the write forms (Automations edit, Assistants); `approval-card.tsx` — `ApprovalCard`, an Assistants approval worded by the core with Approve / Deny that echo the card's own `actionHash` (expired cards cannot be answered).
- `section.tsx` — `SectionLabel`, `Card` and `CardRow` (a card drawn row by row, for virtualized lists — Sessions and Changes are FlatLists): the page-level layout vocabulary (gutter `spacing.screen`, card corner `radii.lg`, row metrics `row.*`); screens never restate border/radius/background.
- `motion.tsx` — shared motion: `Reveal` (ease in/out, staggered by index and only for the first `motion.maxAnimated` items; `layout` slide is opt-in for a handful of blocks, never for every row), `Fade`, `Chevron` (turns on open), `ProgressBar` (eased fill), `Skeleton`, `PulseRing` (blocked dot halo). Durations come from `motion` tokens; loops stop under reduced motion.
- `skeletons.tsx` — `ListSkeleton`, the loading shape of Home / Sessions / Quota / Changes (replaces centered spinners).
- `pull-refresh.tsx` — `pullRefresh(refreshing, onRefresh)`: a factory (RN clones the element and nests the ScrollView in it, so it must be a real RefreshControl, never a wrapper component) returning the themed RefreshControl (Android has no negative overscroll for a JS-drawn indicator, so the native control is the animation).
- `status-slot.tsx` — the one 16pt status slot (working = spinner, idle/done = hollow ring, other = solid dot; a blocked dot breathes a `PulseRing`; `ServiceSlot` = the same slot as a rounded square for a running service).
- `chat/chat-page-view.tsx` (+ `.web.tsx`) — host of the shared Chat page: react-native-webview (iframe on Web) loading `CHAT_PAGE_HTML` offline with the `mygo` shim; page calls → `onCall`, each state → `chat:updated`; web links leave for the system browser.
- `chat/chat-header.tsx` — `ChatHeaderTitle`, the two-line identity title the Chat screen and the `/compose` draft share: agent name (Bot glyph) over `provider · Workspace · age`; missing meta parts drop out of the line.
- `sessions-drawer.tsx` — the Home drawer content: one head block (the instance switcher), an Agents | Workspaces two-way switch like the desktop sidebar's (`state/drawer-store`, memory only, default Agents; the needs-you count is a badge on Agents), and one bottom block, the HostSwitcher. Agents = agent panes grouped by Workspace (blocked, working, then by last worked) with the status slot at the row end; Workspaces = a tile row per Workspace (letter, name, pane tally, its most urgent status) folding open into every pane, Terminals included. A pane row opens it (client-local, never moves the Mac).
- `host-card.tsx` — the Mac card of Connection settings: live status, address:port, route, certificate tag, last connected + phone network, first-paired date, earlier addresses; tap = switch, Reconnect (active), Forget behind a confirmation.
- `host-switcher.tsx` — the drawer's one bottom block: the active Mac (name over an honest status line — Connected · route · address, or Can't reach this computer) and a gear straight to Connection settings. No fold and no Manage row: switching Macs lives in the head's sheet, adding/managing in Connection.
- `pane-row.tsx` — Home's pane card: the title on its own line (up to two), a small line under it with provider · Workspace · age, one-line peek, status slot; a folded `BackgroundList` below it lists the agent's sub-agents (circle) and its pane's service (square), open while something works, sub-agent tap → its Chat drawer (`?subagent=`), service tap → read-only alert.
- `launch-composer.tsx` — Home's new-session card (option C). On Home (`collapsible`) it is a slim bottom card that rises over a dimmed list on tap (one motion with the keyboard it focuses at once — no spring, no layout animation) and folds back after a send / tap outside / Back; light form = folder chip, Agent/Terminal mode, agent chip, prompt (Terminal: its first command, one line, typed into the new shell by the Host), send, and "open full composer" (agent mode) that hands the draft to `/compose`. Share page: same form, always open. An agent send with Chat served navigates at once to the pending Chat screen (`pending-<requestId>` — that screen runs the one `client.launch` while the prompt already stands in as its first row); a Terminal send keeps the round-trip. Both hand-offs and the open-full grow the next screen out of this card (`lib/zoom-origin` + `ZoomIn`).
- `launch-pickers.tsx` — `Chip`, `FolderSheet`, `AgentSheet`: the folder/agent choosers shared by `launch-composer` and `/compose`.
- `keyboard-inset.tsx` — the one keyboard-avoidance wrapper (reanimated useAnimatedKeyboard); Home and Chat lift their bottom composer with it, never KeyboardAvoidingView.
- `changes-button.tsx` — header button of Terminal (Chat reaches Changes through its ⋯ menu); resolves the pane's Workspace from the tree and opens `/changes/[workspaceId]`; renders nothing without `capabilities.git`.
- `status-badge.tsx` — the one-letter Git change badge (M/A/D/R/U) used by the Changes file rows.
- `option-sheet.tsx` — plain RN Modal bottom sheet for the composer's folder/agent pickers.
- `native-terminal.tsx` — Android/iOS xterm WebView renderer; touch is inert so only typed input reaches the pane.
- `route-notice.tsx` — the one banner that says the network path changed (Direct ⇄ Relay), ~3.5 s, tap to dismiss; text from `state/route-notice-store`.
- `error-boundary.tsx` — recoverable render failure boundary.

Rule: components are presentation owners. Host queries, provider/session files, Herdr focus, and runtime lifecycle stay in feature controllers/services.
