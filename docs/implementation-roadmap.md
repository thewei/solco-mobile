# Solco Mobile Implementation Roadmap

Status: **Conversation convergence implementation in progress; read-only real-Host mobile QA is verified against the current Host build, while mutating flows, live shared-TUI and native acceptance remain open**
Baseline: 2026-08-31
Architecture: `mobile-product-architecture.md`
UX contract: `mobile-ui-ux.md`
Web/PWA track: `web-pwa-architecture.md` + `web-implementation-plan.md`

## Guiding rule

Build one phone-native client over the Solco Host API. Do not let mock UI, transport implementation, or native platform code become a second runtime/domain authority.

Web track rule: the Web build is the same mobile client compiled to DOM via react-native-web — not a second product, not a second interaction contract. Web/PWA sequencing lives in `web-implementation-plan.md`; W-phase acceptance is binding like M-phase acceptance.

## 2026-08-30 convergence evidence (Current, not a plan claim)

The approved Batch 0–10 handoff is being executed in order. Verified implementation currently covers
the following boundaries:

- Batch 0: installed Herdr 0.8.2 / protocol 20 probe recorded global focus/resize semantics and no
  client-local isolation. Product accepts that shared behavior; the Host/Remote implementation now
  advertises `herdr_tui=true`, with runtime/operator and native VT verification still open. No Pane
  fallback is permitted.
- Batch 1–2: Host semantic Conversation DTOs and shared Continue transaction seam are implemented and
  unit-tested, including exact AgentSessionInfo correlation and exactly-once prompt call matrix.
- Batch 3–4: Remote API v2 routes/capabilities, `conversation.updated`, and Mac-authoritative golden
  fixtures are implemented; Mobile fixtures are byte-identical copies.
- Batch 5–7: Mobile Query/client contracts, one ConversationSurface, Live Agent Chat migration, and
  History list/detail Continue transition are implemented. The shared Markdown adapter intentionally
  uses a bounded plain-text fallback until a compatible rich renderer is verified. Remaining native/Web
  acceptance is tracked below and is not implied by these source changes.

Batch 8–9 (Remote/Mobile TUI) source implementation is landed as one Host-owned shared/global TUI
session. Batch 10's IA cleanup is source-audited: normal Agent Board terminal sections and Pane navigation are gone, while
the legacy Pane file remains only as an opt-in diagnostic tombstone. Overall convergence acceptance
still remains open for live shared-TUI attach/stream/input/resize/reconnect/close, native/device gates,
and operator-level runtime flow.

## W - Web/PWA validation track

Status: **W0/W-polish/W-engage/W-terminal complete (2026-08-25); W1 de facto done (R6 loopback API implemented with full P0/P1 endpoint coverage); W2 live-Host loop verified (terminal I/O chain end-to-end); W3 PWA assets implemented (HTTPS install acceptance pending); W4 pending**

Goal: validate the full stack cheaply — RN tree on web, Host client boundary against a real Host, and an installable PWA path — before deeper native investment.

Phases (details, work items, and the step checklist live in `web-implementation-plan.md`):

- W0 platform seams: web connection persistence (baseUrl only; credential stays session-memory), desktop phone-width shell, and a real-Host walkthrough;
- W1 R6 minimal slice gate: four endpoints (`hello`/`bootstrap`/`agent detail`/`prompt`), snake_case wire, dev-only CORS flag — owned by solco R6;
- W2 live Host loop: HTTP client against loopback, contracts-layer wire→internal transform, polling-based event fallback;
- W3 PWA layer: manifest + icons, install acceptance over Tailscale HTTPS (non-secure LAN IP is a hard blocker for install);
- W4 Host-served web bundle: Axum ServeDir mounts `dist/` same-origin (solco, R8 window).

Acceptance gates mirror `web-implementation-plan.md` per phase; the cross-repo rule is that mobile web UI must not outrun the Host gates (solco P6).

## M1 - Host client boundary

Status: **Historical foundation plus current semantic-v2 migration; final native acceptance remains pending.**

Goal: expose one transport-independent Solco Host client backed only by the real Remote API.

Implemented:

- one `HostClient` interface with the authenticated HTTP adapter;
- Zod validation for bootstrap and Agent detail payloads;
- TanStack Query bootstrap/Agent keys and prompt invalidation flow;
- Workspace/Project selection remains client-local and is reconciled against Host bootstrap data;
- Agent Board, Workspace/Project picker, and Agent Detail no longer import fixtures directly;
- optional `EXPO_PUBLIC_SOLCO_HOST_URL` preconfigures the real Host URL; credentials remain session/device scoped;
- no screen-level `fetch` or WebSocket creation.

Remaining:

- keep HTTP DTOs aligned with the current Mac Host semantic-v2 contract — the R6 loopback slice and
  this convergence handoff remain the wire sources of truth;
- semantic Agent wait/interrupt/stop commands;
- WebSocket event client with reconnect/backoff;
- authentication/pairing headers and device credentials;

Acceptance:

- screens consume only the real Host adapter without a second in-memory runtime;
- malformed Host responses fail validation explicitly;
- reconnect refetches bootstrap/current Agent;
- missed events do not cause permanent state drift.

## M2 - Pairing and connection

Goal: connect a physical phone safely to one Mac Host.

Sequence:

1. direct local development endpoint;
2. QR/device pairing contract;
3. credential stored through SecureStore;
4. authenticated LAN HTTPS/WSS;
5. connection status and revoke/re-pair UI.

Acceptance:

- secrets never enter logs/Zustand/plain AsyncStorage;
- expired/revoked credentials fail closed;
- phone can disconnect/reconnect without moving the Mac GUI selection;
- unavailable Host renders a recoverable offline state.

## M5 - Advanced Terminal (Shared Herdr TUI)

Goal: add one real global Herdr TUI backed by the Host-owned shared session and a mature VT renderer.

Current: Batch 0 found global focus/resize and no client-scoped isolation in installed Herdr 0.8.2 /
protocol 20. That contention is an accepted product behavior and is disclosed at the Mobile TUI
entry point. The Host shared lifecycle source is implemented and advertises `herdr_tui=true`; live
runtime/operator and native VT verification remain explicit gates.

Implemented source boundary: one Host-owned shared TUI session, authenticated raw-byte stream,
bounded input/resize/reconnect hooks, and deterministic shutdown/reaping hooks. Deferred acceptance:
live operator attach/stream/input/resize/reconnect/close proof plus an Android-first mature VT
renderer (and subsequent iOS validation), IME/accessory-key UX, and device performance. Never create
a TUI process per remote client, Project, Pane, or Agent.

## M6 - Public remote private beta

Preferred first remote beta:

- Tailscale/WireGuard overlay carrying the same Host API;
- connection diagnostics;
- background/foreground reconnect behavior;
- no cloud account dependency required yet.

Background attention on Android ships as a foreground-service keep-alive plus local notifications
(`features/host/background-bridge` + `modules/solco-foreground-service`). Remote push stays deferred
until store publishing is a real goal: FCM is absent on China vivo ROMs, and vivo's official channel
requires a store listing (个人开发者 + 软著 + App 备案) with per-device daily message quotas.

SSH port forwarding remains developer/advanced fallback, not the primary onboarding flow.

## M7 - Solco Relay

Goal: normal public-internet connectivity without asking users to configure VPN/SSH/router ports.

Mac and phone make outbound authenticated connections to Relay. Relay transports traffic and presence but does not become Herdr/Workspace/Agent authority.

Add push notification infrastructure only at this phase if reliable background attention is required.

## M8 - Native extensions only when justified

Potential local Expo Modules:

- SSH fallback transport;
- specialized network discovery;
- terminal/native rendering acceleration;
- advanced background networking.

Each module needs a concrete capability gap and native-device test before acceptance.

## Current environment gate

Current Mac: **macOS 15.6.1 + Xcode 16.1**.
Expo SDK 54 local iOS requirement: **Xcode 16.1+**.

This is an intentional compatibility baseline. Android is the first implementation/validation platform, so M0 must first include a real local Android Development Build or Gradle debug assembly from CNG-generated native sources. iOS remains supported on the Xcode 16.1 floor and gets its own Development Build gate before iOS-specific work is called complete. SDK 55+ is deferred because it requires the Xcode 26 generation and would violate the local-build requirement.
